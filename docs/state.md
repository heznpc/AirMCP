# 프로젝트 상태 정본 (Project State of Truth)

> **목적: 방향·포지셔닝·시장 질문을 받은 세션은 코드 스캔이나 리서치 에이전트 대신 이 문서에서 출발한다.**
> 결론이 바뀌면 이 문서를 같은 커밋에서 갱신한다. 여기 적힌 것은 날짜 딸린 주장이며,
> 그 위에서 실제 행동할 때만 해당 항목을 재검증한다.
>
> 갱신일: 2026-07-30 · 대외 문구는 [direction.md](./direction.md)가 정본이고, 이 문서는 내부 판단의 정본이다.

## 1. 한 줄 정의 (확정)

AirMCP는 AI 에이전트(Claude, Codex, OpenClaw 등 어떤 두뇌든)가 Mac의 Apple 앱을 만질 때 거치는
**유지되고, 승인되고, 기록되는 손**이다. 비서 본체가 아니라 비서들이 꽂아 쓰는 능력 계층이다.

## 3. 가설의 무덤 (새 외부 증거 없이 재론 금지)

| 가설 | 상태 | 사인(死因) |
|---|---|---|
| "도구 수(297개)가 판다" | 2026-06 폐기 | 주말 클론으로 복제 가능. 비교 화면에서만 유효 |
| "governance가 차별점" | 미검증, 후방 배치 | 외부 요구 증거 0건. 개인 시장에서 호출별 승인은 마찰. 팔리는 곳(기업)엔 판 적 없음 |
| "워크플로가 상품" | 미검증, 기각 | 가장 얇은 계층(텍스트). 모델의 자체 조합 능력이 대체. 사용 흔적 0 |
| "니치가 비어 있으니 차지하면 된다" | 과대 주장으로 정정 | 선두의 죽음은 공급 부패 증거이지 우리 수요 증거가 아님 |

외부 행동으로 실증된 유일한 수요: **"그냥 안정적으로 유지되는 Apple 앱 접근"**. 통제·워크플로는 그 위의 보험/편의이지 입장권이 아니다.

## 4. 운영 모드 (2026-07-30 확정)

- **토큰/시간 지출 허용**: ① 외부 이슈·PR 응답 ② CI 파손·macOS 업데이트 파손 수리 ③ 오너가 명시 지시한 범위.
- **동결**: 포지셔닝 재작성, 전략·니치 분석, 선제적 기능/테스트/문서 확장, 신규 유통 시도.
- 자동화(계약 하네스, 드리프트 가드, dependabot auto-merge, 전 플랫폼 CI)가 무인 유지를 담당한다.
- 브랜드(AirMCP)는 유지한다. 아카이브하지 않는다.

## 5. 오너 결정 대기 (이 문서의 유일한 열린 질문)

**A. 알고 하는 동결** — 재개 트리거(외부 반복 요구·사용 흔적·Apple의 공식 표면 개방·유입 변곡)는 현 유통 수준에서 발화 확률이 낮음을 인정하고, 저비용 보존 자산으로 유지.

**B. 판정 실험 1회 후 동결** — 사전 등록된 kill 조건과 비용 상한을 가진 단일 유통 실험(예: 마찰 최소 채널 1곳에 결과물 1개, N주 내 실사용 지표 미달 시 가설 사망 판정)을 실행하고, 그 결과를 이 문서에 기록한 뒤 동결.

주의: B의 실험 설계는 설치·TCC 권한 마찰이라는 교란변수를 통제해야 하며, kill 조건 없는 실험은 하지 않는다.

## 6. 작업 항목은 여기 없다

열린 부채·결함·오너 결정 대기는 전부 [`docs/ledger.md`](./ledger.md)에 있다.
이 문서는 판단의 정본이고 원장은 작업의 정본이다. 한 항목이 두 곳에 살면 어느 쪽도 정본이 아니다.

과거 이 절에 있던 두 항목은 원장으로 이관됐다 — typescript peer 상한 가드(L-002),
add-on 12종 npm Trusted Publisher(L-008).

## 7. 세션 규칙

1. 방향·포지셔닝·시장 질문 → 이 문서로 답하고, 갱신 필요 시 이 문서를 고친다. 코드 스캔·리서치 에이전트 금지(오너 명시 지시 제외).
2. **무엇을 할지** 묻는 질문 → [`docs/ledger.md`](./ledger.md)로 답한다. 원장에 없는 일은 하지 않는다.
3. §3의 가설을 되살리려면 **새 외부 증거**를 이 문서에 먼저 추가해야 한다.
4. 전략 결론이 세션 대화에만 남는 것은 실패다. 결론은 이 문서 커밋으로만 성립한다.
5. 원장이 비면 새 항목을 발명하지 않는다. 원장 §0.6이 정한 세 쿼리만 돌리고 멈춘다.
